# 名簿・写真の拡張設計

今回の利用画面は出席番号のみで完結する。一般名簿のAI解析・写真ツールとの実接続・名簿読み込みUIは今回の範囲に含めない。

## データ境界

提出記録は`grade + classNumber + date + assignment`で識別し、ランダムな`id`で参照する。各記録に人数と`students`のスナップショットを持たせ、過去の名簿変更で提出記録がずれないようにする。出席番号は1〜40の連番。提出状態は番号→ISO8601時刻の辞書であり、名前や写真をキーにしない。

`Student`には`number`, `name?`, `reading?`, `photoAssetID?`がある。Swift・Web両版のボタンは名前と読み仮名が存在すれば表示する。写真は未表示。`photoAssetID`はローカルのアセットIDとして扱い、外部URLを自動取得しない。

## 厳格な名簿取り込み（実装・ユニットテスト済み）

`StrictCSVRosterImporter`は`RosterImporting`を実装する。UTF-8（BOM可）、見出しが完全一致したCSVを読み取る。

```csv
number,name,reading
1,児童サンプル一,じどうさんぷるいち
2,児童サンプル二,じどうさんぷるに
```

任意の第4列`photoAssetID`も可能。1からの連番・重複なし・1〜40人・名前必須。引用符、値内のカンマ、空行、列数違い、非UTF-8は拒否する。CSV一般仕様の寛容な推測をせず、行番号付きエラーで訂正を求める。現在の画面にファイル読み込みボタンは出さない。

UI導入時は「ファイル選択 → 候補一覧 → 人数・番号・名前の確認 → 明示的に確定」とする。新規記録のstudentsを置き換える前に検証し、保存に失敗したら表示も変更しない。

## 一般名簿／Apple Foundation Models（接続用設計のみ）

`RosterImporting.candidates(from:) async throws -> [Student]`に新しいアダプターを追加できる。PDF・画像はVision等でテキスト化し、表の構造を保持して候補生成へ渡す。Apple Foundation Modelsを利用する場合は対応OS・モデル利用可否を確認し、利用不可なら厳格CSVへ誘導する。AIに欠けた名前・読み仮名の推測をさせない。候補には警告・読み取り元も添付できるよう結果型を拡張し、確定前の全件レビューを必須とする。

今回はモデル呼び出し・OCR・精度検証を含めない。端末内モデルであること、利用できる言語、対応機種について導入時に再確認する。

公式資料: https://developer.apple.com/documentation/FoundationModels/generating-content-and-performing-tasks-with-foundation-models

## 顔写真ツール（接続用設計のみ）

`PhotoAssetResolving.localURL(for:)`がアセットの解決境界。既存ツールの仕様が確定したら、クラスID・出席番号・学年度を含むマッピングからローカル写真をコピーしてIDを発行する。ファイル名や顔認識による自動照合は行わない。書き出しには写真を含めず、写真の削除・更新を提出データから独立して扱う。

既存の顔写真ツールには今回アクセスしていない。実装時には形式・ID・保存場所の確認が必要。

## 移行とプライバシー

現在の`schemaVersion`は1。旧記録のオプションフィールドが欠けても番号のみで読み込める。未知のバージョン・破損ファイルは上書きしない。バックアップには将来追加する氏名等も入るため、名簿UIを有効化するときに保存・削除・持ち出しのルールを設ける。WebにクラウドAIや外部写真取得を黙って足さない。
